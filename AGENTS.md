# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product Decisions

- Online transcription failures are never silent: retry exhaustion surfaces a persistent, actionable banner in the transcript view (plus a one-time toast) with 「改用本地 Whisper」/「更换转写服务」 deep links into the matching settings form; terminal 4xx configuration errors skip the live-retry backoff. 本地 Whisper is a first-class shortcut in the prepare card and onboarding, and switching profiles mid-recording applies from the next 8-second chunk without restarting the recording.

- Audio captured while the transcription model is not ready is never lost (desktop + iOS parity, the no-gap guarantee): desktop treats 主进程 `[STT_NOT_READY]`-marked failures (local model missing/downloading, no profile selected) as recoverable — affected 8-second chunks park in a per-track backlog (capped ~8 minutes of audio, overflow drops oldest), a sequential drain loop re-sends the oldest parked chunk every 4s/8s/15s with the profileId re-resolved at send time (mid-recording profile switches apply), provisional placeholders stay visible, later chunks never commit ahead of parked ones, and the first drained success fires onTranscriptionRecovered; terminal 4xx parked entries give up that chunk instead of retrying forever, and starting without any STT profile boots the transcription loops the moment one is configured. iOS creates the SFSpeechRecognizer task whenever authorized even when the recognizer is unavailable, a per-3-second watchdog rebuilds missing tasks during recording, unavailable windows are tracked as gap ranges (closed at each stream restart), and after stop each gap is trimmed from the archived CAF via AVAssetExportSession (M4A) and backfilled with SFSpeechURLRecognitionRequest, merging paragraphs into the meeting transcript in time order — a whole-recording gap therefore fills in shortly after stop instead of staying empty.

- Desktop transcript UI follows the supplied meeting-assistant reference's reading hierarchy: a collapsible meeting-overview card above a chronological feed, speaker identity chips and seekable timestamps above soft paragraph bubbles, with compact follow controls. Preserve MinuteFlow's warm light/coral palette and verbatim editable transcript; the overview is an excerpt of existing minutes, never AI commentary mixed into the original speech or a new request triggered by opening this view.

- The product is a local-first Electron desktop meeting assistant for Windows 10 22H2+ and macOS 14.2+.

- AI 问答的回答在渲染层做打字机平滑（Codex 观感）：流式增量先入缓冲队列，按真实模型生成速度出字——约 40 字/秒起步、随缓冲增大提速（160 字/秒封顶），130 字回答约 3-4 秒铺完；出字在标点处断句并小停（句号约 120ms、逗号约 40ms），带自然呼吸而非机械匀速；小增量一两拍内透出紧跟真实生成节奏，被网关缓冲/降级的整包也有界铺完；等待期间以打字点动画提示。AI 问答不提供「思考过程」展示入口：思维链仍在传输层拆分（防内联 <think> 泄入正文）但不渲染。浏览器预览的模拟到达速度同样对标真实 API（约 50 字/秒）。
- 转录文本在渲染层做与 AI 问答同一节奏的流式揭示（共享 typewriter 核心）：导入/直播中新到达的段落与追加文本进入揭示队列，按 40 字/秒起步、随缓冲提速（160 字/秒封顶）逐拍铺开、标点处断句小停，一段铺完再铺下一段；非追加的识别修正立即到位不重打；历史内容、切换会议与 Reduced Motion 直接透传，绝不打字机。

- FFmpeg is an app-managed bundled runtime on desktop. Recording preparation, audio import, local transcription, and diarization must use the packaged binary without searching the system PATH or asking users to configure an FFmpeg path.
- Remote transcription requests use a minimum 330-second client timeout so a recommended 300-second Synology DSM reverse-proxy read timeout can return first with a 30-second transport/error-handling margin; upgraded profiles with older shorter values are raised at runtime.
- New API is a provider/gateway preset, not a protocol. Its transcription path uses the standard OpenAI-compatible `/v1/audio/transcriptions`; saved legacy `new-api` flavors migrate to `openai`, full transcription URLs are accepted as Base URLs, and connection tests must POST a bundled WAV rather than merely query `/models`.
- Remote transcription retries transient failures inside the client: HTTP 429/5xx responses and fast network errors get up to two extra attempts with 2 s/8 s backoff (caller cancellation aborts the backoff immediately), so a single gateway hiccup cannot pause a long import; 4xx configuration errors and the 330-second timeout are never retried, and the final error message renders the gateway's `error.message` plus its request id (response header or embedded text) instead of a raw JSON blob. Exhausted retryable failures carry a `retryable` flag: the import queue then enters a recoverable `waiting_for_network` state and auto-resumes from its persisted chunk checkpoint with growing backoff (15 s/30 s/60 s/120 s, capped at 5 min; the counter resets after one successful chunk, and app restart resumes the same state), while live meeting chunks retry in the renderer with 1.5 s/5 s/15 s backoff before leaving a gap in the transcript.
- AI-generated transcripts and meeting summaries are normalized to Simplified Chinese. Desktop 8-second live chunks and roughly 10-second import chunks are transport/progress units only, never visible paragraph boundaries. Desktop and iOS group atomic recognition fragments into natural speaking paragraphs using speaker/track changes, 1.5-second pauses, terminal punctuation, conservative topic openers, two-sentence soft boundaries, and 120-character/45-second safety caps while preserving stable timestamps and the first fragment id. Completed historical meetings are never automatically resegmented.

- The meeting library pins favorited meetings in a top “收藏” group with an inline hover star toggle; searching falls back to plain time groups with the matched term highlighted in titles.
- Desktop transcription offers macOS's built-in Apple Speech as a first-class on-device option: transport `apple-speech` runs the prebuilt universal Swift helper (`resources/apple-speech/mf-apple-speech.swift` → `scripts/build-apple-speech.sh` → `resources/bin/`, not committed; forge `prePackage` builds it if missing, `extraResource` ships it with the `resources/fixtures` Chinese test WAV). It is completely free, requires NO model download, defaults to `requiresOnDeviceRecognition` (audio never leaves the device) with `addsPunctuation`, and is mapped from the language preference via `mapLanguageToLocale` (auto/zh → zh-CN). The helper MUST be spawned by the GUI app (TCC attribution): a bare shell/node spawn aborts with a TCC privacy violation, and the dev Electron shell gets `NSSpeechRecognitionUsageDescription` injected by `scripts/patch-dev-electron-plist.mjs` (postinstall) while packaged builds get it from forge `extendInfo`. Critical implementation detail learned the hard way: the helper's main thread must keep running the RunLoop while waiting — a DispatchSemaphore block starves Speech's callback delivery and every recognition times out with zero callbacks. Chunk audio is normalized to 16k WAV via the managed FFmpeg before the helper (AVFoundation cannot read WebM); the settings 「测试连接」 runs a REAL recognition of the bundled sample (which also surfaces the system speech-permission prompt at a user-initiated moment), and timeout errors point to 系统设置 → 键盘 → 听写 for offline assets. TCC attribution has a second layer learned the hard way: the PACKAGED app itself must be launched through LaunchServices (`open -a MinuteFlow`) — launching `MinuteFlow.app/Contents/MacOS/MinuteFlow` directly from a terminal makes the terminal the responsible process, so every helper speech request crashes with `__TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION` regardless of signing; signing was never the variable.
- Apple Speech import transcription applies built-in speech conditioning and offers an opt-in online mode, both born from measured coverage on a 336-second near-continuous Chinese meeting MP3: import chunk extraction for the `apple-speech` route runs `highpass=f=70,loudnorm=I=-16:TP=-1.5:LRA=9` on the 16 kHz WAV (the meeting file measured ~-30 dB mean loudness; conditioning alone roughly doubles recognized chars), with a no-filter fallback if FFmpeg rejects the filter chain — Whisper-class engines have robust front-ends and get no filters. The on-device recognizer is at its ceiling on difficult continuous speech (≈26–37% slot coverage regardless of conditioning or chunk size), so the settings page exposes 「使用 Apple 在线识别」 (`options.allowServer`, default off — audio never leaves the device) which routes recognition through Apple's server model; end-to-end through the product pipeline the same meeting went 36.8% coverage / 176 chars (0.1.35 baseline) → 66.2% / 433 chars with conditioning + online mode. Apple Speech import chunks use a 30-second silence-aware window (10-second mid-sentence cuts trigger mass no-speech verdicts) with the helper timeout raised to 100 s; live recording keeps its 8-second transport chunks.

- Meeting playback supports cycling playback rates (remembered for the session) and Space / arrow-key transport controls that yield to any focused text input; update-available toasts deep-link straight to “设置 → 软件更新”.
- Desktop speaker labels use a local-only voiceprint book: renaming a diarized speaker enrolls that person from the meeting's verified local audio, and future diarization applies the saved name only when similarity and runner-up separation are both confident. Voice embeddings never leave the device, low-confidence matches remain generic, model-incompatible samples are ignored, and users can forget an identity without changing historical transcripts. Every sherpa-onnx-node call that returns samples or embeddings must pass the copy flag (`readWave(path, false)`, `extractor.compute(stream, false)`), because Electron's V8 forbids external buffers and throws "External buffers are not allowed" otherwise. Full-file speaker diarization runs in a utilityProcess worker (`diarization-worker.mjs`) over the shared pure core (`diarization-core.mjs`) so synchronous ONNX inference never blocks the Electron main event loop — a 34-minute file takes ~4.5 minutes of CPU; voiceprint enrollment (≤30 s of audio) stays in-process.
- Visual meeting minutes are a cross-platform structured enhancement, never the factual source: a verified online summary model returns a constrained `VisualSummary` JSON and Electron/SwiftUI render it natively. Models must not return HTML, Markdown, image URLs, arbitrary styles, or Chinese text baked into generated images.
- Visual-summary capability is opt-in and verified by a real schema-validating request. Changing the provider, endpoint, protocol, or model invalidates that verification; model-name heuristics must never enable the feature.
- A final visual summary is generated only after the ordinary structured summary succeeds. Its second-stage request contains only the ordinary summary and necessary meeting metadata, never audio or the full transcript; ordinary-summary failure skips the visual request, while visual failure preserves the ordinary summary and marks any older visual summary stale.
- Electron and iOS export valid visual summaries as locally rendered PNG files. Existing ordinary exports and backups remain available, JSON backups preserve the visual schema, and a stale or missing visual summary must not appear as an export option.
- First launch must guide users through transcription and summary setup after permissions: desktop points users to the real Whisper and AI-summary settings workbenches and resumes the wizard on return; iOS offers Apple Speech or remote Whisper, then local-basic or online summary. Skipping Whisper means audio-only capture, while skipping the large model explicitly selects the local basic-summary fallback; neither choice may trigger a remote request during recording finalization.
- Desktop online live transcription must normalize short browser-captured WebM/MP4 chunks to 16 kHz mono PCM WAV with the app-managed FFmpeg before upload. Some OpenAI-compatible gateways parse duration before transcription and reject duration-less WebM chunks; archived source audio remains unchanged.
